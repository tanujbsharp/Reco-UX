# Bsharp Reco — Implementation Reference

A feature-level reference of what is built in the current Reco codebase. Use this as the source for writing user-facing feature descriptions.

---

## 1. System Summary

Bsharp Reco is a guided retail recommendation system for laptops. It turns vague customer intent ("something for college", "for my kid", "for coding") into a top-3 product shortlist with explanations, comparison, product Q&A, and lead capture.

- **Backend:** Django 4.2 + DRF (Python 3.13)
- **Frontend:** React 18 + TypeScript + Vite + Tailwind
- **LLM:** Amazon Bedrock (Claude Sonnet)
- **Speech-to-Text:** OpenAI Whisper (base model, CPU)
- **Storage:** MySQL (Reco DB + Converse DB read-only) + Amazon OpenSearch + S3
- **Email:** Amazon SES

---

## 2. Customer Journey (End-to-End Flow)

The frontend implements 13 screens that walk a customer from arrival to lead capture:

| Step | Screen | What Happens |
|------|--------|--------------|
| 1 | Landing | Session entry point; tenant/outlet branding |
| 2 | Consent | Customer agrees to data capture |
| 3 | Discovery Mode | Choose: voice, text, or skip to questions |
| 4 | Voice Discovery | Live mic recording with transcription |
| 5 | Voice Results | Editable preference tags from transcript |
| 6 | Guided Questions | Single-card adaptive question flow |
| 7 | Processing | Recommendation engine running |
| 8 | Recommendations | Top 3 picks with star feedback |
| 9 | Comparison | Side-by-side product comparison + chat |
| 10 | Product Detail | Full specs, gallery, accessories, finance + chat |
| 11 | Lead Capture | Customer name, phone, email |
| 12 | Share/Save | Email recommendations to customer |
| 13 | Confirmation | Thank-you and reset for next customer |

## 3. Implemented Features

### 3.1 Voice & Text Discovery
- Browser MediaRecorder captures voice (WebM/Opus, max 2 min)
- Backend converts to WAV via ffmpeg, transcribes using Whisper base model on CPU
- Auto language detection (90+ languages supported by Whisper)
- LLM extracts preference tags from transcript (e.g., "lightweight", "student", "coding")
- Customer can edit tags before proceeding
- Text input mode for customers who prefer typing
- Skip option to bypass discovery and go straight to questions

**Backend:** `apps/voice/`
**Frontend:** `VoiceDiscoveryScreen.tsx`, `VoiceResultsScreen.tsx`, `DiscoveryModeScreen.tsx`

### 3.2 Adaptive Guided Questions
- LLM-generated questions based on session state, catalog, and prior answers
- No pre-authored question bank — fully dynamic
- Moderation-aware: question generation respects rules from RAG-indexed moderation docs
- Auto-stops when confidence threshold reached or max questions hit
- Single-card UI with auto-advance on answer

**Backend:** `apps/questions/orchestrator.py`
**Frontend:** `GuidedQuestionsScreen.tsx`

### 3.3 Recommendation Engine
- Weighted scoring: `Score = Σ (Feature_Weight × Feature_Fit)`
- Weights adjusted by voice tags, customer answers, benefit mappings
- Multi-stage pipeline: hard filters → geography modifiers → moderation overrides → feedback patterns → diversity
- Preference inference from natural-language input
- Outputs top 3 ranked recommendations

**Backend:** `apps/recommendations/scoring.py`, `preference_inference.py`, `preference_profile.py`

### 3.4 Explainable Recommendations
- Per-product "Why this product?" explanation generated by LLM
- Includes fit summary, key highlights, pros, cons, tradeoffs, salesperson tips
- Cached in MySQL to avoid redundant LLM calls

**Backend:** `apps/recommendations/explanation.py`

### 3.5 Side-by-Side Product Comparison
- Two-product comparison interface
- LLM generates commentary on differences, tradeoffs, and best-fit scenarios
- "Learn Once, Serve Forever" caching: comparisons cached across all outlets
- Cache invalidated only when product features change

**Backend:** `apps/comparisons/`
**Frontend:** `ComparisonScreen.tsx`

### 3.6 Product Detail View
- Full specs, hero image, gallery
- Accessories with pricing
- Finance schemes (EMI/lease) with validity dates
- Brochure text
- Floating chat widget for product Q&A

**Frontend:** `ProductDetailScreen.tsx`

### 3.7 Product Chat (RAG-Grounded)
- Floating chat button on product detail and comparison screens
- Customer questions answered using OpenSearch product knowledge base (specs, FAB, crawled content)
- Bedrock generates grounded answers from retrieved chunks — no hallucinations

**Backend:** `apps/product_chat/`

### 3.8 Brand Moderation & Business Rules
- **Knowledge documents (RAG):** Admin uploads plain-English rules → chunked → indexed in OpenSearch → injected into LLM prompts at runtime
- **Business overrides (MySQL):** Campaign boosts, SKU pushes, suppression rules
- Minimum fit threshold: overrides only apply if product meets baseline fit
- Per-tenant isolation

**Backend:** `apps/moderation/`

### 3.9 Customer Feedback & Learning Loop
- 5-star rating on top-3 recommendation set (not per product)
- Feedback stored with full context: voice tags, answers, scoring weights, products shown
- Nightly Django Q job analyzes input→output patterns
- Patterns indexed to OpenSearch and injected into future LLM prompts to avoid poorly-rated combinations

**Backend:** `apps/feedback/`

### 3.10 Lead Capture
- Customer PII (name, phone, email) with consent
- Lead record links: selected product, recommended products, full journey
- Preference data and interaction history stored for CRM follow-up

**Backend:** `apps/leads/`, `apps/customers/`
**Frontend:** `LeadCaptureScreen.tsx`

### 3.11 Email Share (SES)
- One-click share of recommendations to customer email
- Includes product details, recommendation reasoning, session context
- Customizable email template per packet
- Message ID tracked for audit

**Frontend:** `ShareSaveScreen.tsx`

### 3.12 Web Crawling & Content Enrichment
- Triggered automatically on product upload
- Per-brand crawl selectors configured in Django Admin
- LLM fallback when HTML selectors fail
- Async via Django Q
- Extracts descriptions, highlights, images, gallery URLs

**Backend:** `apps/crawl/`

### 3.13 Analytics & Event Tracking
- All events (sessions, transcriptions, questions, views, chats, feedback, handoffs, shares) stored in MySQL + OpenSearch
- Role-based filtering: brand admin sees all outlets, store staff sees own outlet

**Backend:** `apps/analytics/`

### 3.14 Authentication
- Reuses existing Converse login system (Angular module)
- Session-based auth
- Read-only access to Converse DB for users, companies, roles

**Backend:** `apps/converse_auth/`

### 3.15 Packet Management
- Each tenant/brand has its own "packet" — independent product catalog, scoring config, moderation rules, lead capture template
- Lenovo PSREF catalog seeded for the demo packet

**Backend:** `apps/packets/`

**S3:** product images, brochures, gallery, moderation docs, audio temp files

## 5. Key Capabilities Summary (for feature writing)

| Capability | One-line description |
|------------|----------------------|
| Voice / Text / Skip Discovery | Customer expresses needs in their own words, or skips |
| Adaptive AI Questions | LLM generates the right questions, not a fixed survey |
| Top 3 Explainable Recommendations | Every pick includes a "why this fits" rationale |
| Side-by-Side Comparison | Two-product comparison with AI commentary |
| Product Detail + Chat | Full specs, gallery, accessories, financing, plus Q&A |
| Brand Moderation | Plain-English rules + business overrides, no-code |
| Self-Learning Loop | Star ratings teach the system what works |
| Lead Capture & Email Share | Every interaction → trackable lead + email handoff |
| Per-Outlet Analytics | Conversion patterns, top products, drop-off insights |
| Web Crawl Enrichment | Product KB stays current with brand site content |
